# 2026.296.1043 — feat(crabbox): add describe + containerd-preflight and the containerd e2e bed

## Summary

W6 of the containerd/crabbox programme: make the `crabbox:` verb able to prove a
containerd lease, and make every dependency that is still absent SKIP VISIBLY
instead of being mocked or reported as a pass.

`verb:crabbox` gains two read-only methods and the containerd input block:

- **`describe`** — `crabbox providers describe <name> --json`. The provider is a
  POSITIONAL argument (that CLI command defines no `--provider` flag); a step
  asserts one field with `json_path:`. This is how a bed reads the containerd
  provider from the CLI's own vocabulary.
- **`containerd-preflight`** — the gate for a containerd lease. It probes, in the
  venue: the CLI's provider catalogue, `providers describe containerd`, the
  daemon (`nerdctl info` at the configured address/namespace), the kernel's
  `xt_multiport` match, and the lease image (local inspect, then a real
  `nerdctl pull`). The first absent dependency returns a SKIP naming it exactly;
  a provider that IS present but cannot describe itself is a FAIL. No lease is
  created, mutated or released.
- **`containerd:`** — the provider's own keys, passed as `--containerd-<key>
  <value>` on the same measured allowlist as `--provider` (`doctor`, `leases`),
  never on `providers`/`describe`.

New bed `box/check-crabbox-containerd-e2e/`: a `disposable: true` VM whose guest
runs containerd (crun/krun handlers) with the CLI in the venue. Its plan asserts
the daemon, the CLI's version, and the preflight — which today SKIPS and names the
dependency that still blocks the mutating cycle.

**The mutating `crabbox run --provider containerd` lease and the native
checkpoint -> fork -> restore cycle are NOT authored as `run:` steps yet, on
purpose.** A `run:` step has no conditional SKIP in the check engine (only a verb
verdict can skip); with the dependencies below still absent, authoring it would
ship a red bed that fails on a missing resource instead of naming it. The gate is
authored first, and the cycle lands behind it (R8). The exact blockers:

- the **source-built CLI** — `opencharly/layer-crabbox#16` builds
  `opencharly/crabbox` b7b5aaa3; this repo's fixture pins the last RELEASE-based
  layer tag (v2026.293.1705), whose CLI has no `containerd` provider at all, so
  the preflight skips naming that pin. Producer-first: this PR's pin bump follows
  the layer merge + tag;
- the **lease images** — W5 has not started: there is no `pod-crabbox-coordinator`
  repo and no image workflow, so `ghcr.io/opencharly/pod-crabbox:2026.293.1655`
  (the ref the preflight checks) is unpublished;
- the **native checkpoint seam** — W2 seam 2 (`containerd-commit`) is unmerged and
  has no PR (the local `feat/containerd-commit-checkpoints` branch was never
  pushed);
- **`xt_multiport`** — absent on this host kernel, so the CNI portmap hook cannot
  publish a lease port (`opencharly/layer-containerd#5`).

Refs #15.
