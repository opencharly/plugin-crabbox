The e2e skip message is the point of this PR: it no longer names the CLI pin. It
advanced twice as the stack gained the provider's real dependencies:

1. before the nerdctl layer: `... is not reachable: bash: line 1: nerdctl: command not found`
   — the provider's CLIENT was missing (the containerd layer ships the daemon and
   crictl, not nerdctl); fixed by composing `layer-nerdctl` in this PR;
2. now: `... is not reachable: level=fatal msg="rootless containerd not running"`
   — `nerdctl` running as the venue user resolves to ROOTLESS containerd, while the
   guest's daemon is the rootful system service. The provider's rootful contract
   needs socket access (or a rootless daemon / `containerd.rootless: true`); that
   posture, the unpublished W5 lease image, W2 seam 2 and `xt_multiport` are the
   remaining gate items, tracked on #15. None is mocked; each is named by the
   preflight.
