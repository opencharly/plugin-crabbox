# 2026.289.1122 — docs(skill): point the crabbox reference at the renamed `crabbox-cli` (producer sweep for marketplace#469)

## Summary

Sweeps this repo's one live reference to a renamed skill. `opencharly/layer-crabbox` renamed its projected skill `crabbox` → **`crabbox-cli`** (merged, tag `v2026.289.1044`), so `/charly-tools:crabbox` no longer resolves.

**Why the rename:** two opencharly repos declared one skill name — `layer-crabbox` (the CLI candy) and `plugin-crabbox` (its `crabbox:` check verb). The corpus tolerates both; the umbrella's **derived** harness binding does not, because it is a flat farm of entries named after the skill: `FAIL: corpus skill name collisions across families (a flat farm cannot bind both)`. That stops `charly task sync` and the whole umbrella pin advance (`opencharly/marketplace#469`).

**Swept:** ``candy/plugin-crabbox/charly.yml`` — authored content in this repo, not a marketplace projection. `CHANGELOG/` is deliberately untouched: history keeps the old spelling.

**How this was found.** A corpus regeneration that should have been clean still carried the old reference in `build/skills/docs/SKILL.md`, the projection of this file — i.e. three swept producers were not enough, and this repo was one of two still missing. Producer-first: a stale `/charly-<family>:<skill>` reference is a hard error in the docs build.
